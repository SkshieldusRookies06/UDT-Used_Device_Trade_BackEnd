## 1. 전체 구조

```
┌──────────────┐        ┌───────────────────────────────────────┐      ┌──────────┐
│   브라우저    │        │          Spring Boot (8080)           │      │ MariaDB  │
│              │        │                                        │      │  (3307)  │
│  React SPA   │──REST──▶  Controller ─▶ Service ─▶ Repository ──┼─JPA─▶│          │
│   (5173)     │  JSON  │      ▲            ▲                    │      │  udt     │
│              │        │      │            │                    │      └──────────┘
└──────────────┘        │  @RestController  │                    │
                        │                   │                    │
┌──────────────┐        │  @Controller      │                    │
│   브라우저    │──HTML──▶  + Thymeleaf ─────┘                    │
│  (관리자)     │  Form  │      (View)                            │
└──────────────┘        └───────────────────────────────────────┘
```

**서버는 계층형 아키텍처(Controller – Service – Repository)다.**
사용자 화면의 View는 React가, 관리자 화면의 View는 Thymeleaf가 담당하며,
**두 진입점이 같은 Service를 공유한다.** Service가 웹 타입(`ResponseEntity`·`Model`)을
전혀 모르기 때문에 가능한 구조이고, 이것이 계층 분리가 실제로 지켜지고 있다는 증거다.

프론트엔드는 계층이 아니라 **컴포넌트 기반 단방향 데이터 흐름**으로 구성했다.
상태가 화면을 만들고, 이벤트가 상태를 갱신한다.

## 2. 백엔드 패키지 구조

```
com.rookies6.udt
├── UdtApplication.java
├── config/          CorsConfig · SecurityConfig · JpaAuditingConfig
├── common/          ApiResponse · PageResponse · ErrorCode
│                    BusinessException · ErrorResponse · GlobalExceptionHandler
├── entity/          User Category Product ProductImage Wish
│                    Transaction Dispute DisputeFile + Enum 5종
├── repository/      JpaRepository 8종
├── security/        JwtTokenProvider · JwtAuthenticationFilter
├── controller/      @RestController — /api/**
├── service/         비즈니스 로직 (웹 타입을 모른다)
├── dto/             요청·응답 전용 객체
└── admin/           @Controller — /admin/** (Thymeleaf)
```

> `security/`·`service/`·`admin/`은 목표 구조다 — D1 스캐폴드에는 비어 있고 T-004·T-005·T-006·T-009·T-018이 채운다. **D8에 실물 트리로 재발췌한다.**

**패키지는 계층으로 나누고, 담당자는 리소스로 나눈다.**
`Product*` 관련 파일(Controller·Service·Repository·DTO)이 한 담당자에게 묶여 있어야
한 기능을 끝까지 구현하고 설명할 수 있다.

## 3. 계층 규약 (기계 검사 가능)

| # | 규약 | 이유 |
|---|---|---|
| B1 | Controller는 요청 검증 + Service 호출 + 응답 반환만. **DTO 변환은 Service 안에서** | 컨트롤러에서 변환하면 지연 로딩이 트랜잭션 밖에서 열려 N+1 또는 `LazyInitializationException`이 난다 |
| B2 | Controller에서 Repository 직접 호출 금지 | 비즈니스 로직이 컨트롤러로 새는 것을 막는다 |
| B3 | Service에 웹 타입(`ResponseEntity`·`HttpServletRequest`·`Model`) 금지 | REST와 Thymeleaf가 같은 Service를 부를 수 있게 한다 |
| F1 | 서버 통신은 `src/api/`에서만 | 계약이 바뀔 때 고칠 곳이 한 곳이 된다 |
| F2 | 화면 간 공유 상태는 URL 쿼리 우선 | 새로고침·뒤로가기·링크 공유가 따라온다 |
| F3 | 컴포넌트 200줄 초과 시 훅·유틸로 추출 | 계층을 미리 만들지 않고 커진 뒤에 나눈다 |

검사 명령은 `SPEC.md` §8에 있다.

## 4. 응답 형식 표준화

모든 REST 응답은 동일한 봉투를 쓴다.

```json
{ "success": true, "data": …, "message": "…", "timestamp": "2026-09-22T14:03:00+09:00" }
{ "success": false, "statusCode": 404, "code": "PRODUCT_NOT_FOUND",
   "message": "상품을 찾을 수 없습니다", "timestamp": "…" }
```

- 에러 응답은 `@RestControllerAdvice` **한 곳**에서만 생성한다.
- 프론트는 axios 인터셉터 한 곳에서 봉투를 벗기고 `success`로 분기한다.
- 목록 응답은 `data.content[]` + `data.page{…}` 구조로 고정한다(0-base).

## 5. 인증·인가 구조

```
@Order(1)  /api/**   stateless · JWT 필터 · CSRF off · CORS 적용 · 401은 JSON
@Order(2)  /admin/** 세션 · formLogin · CSRF on · 403은 HTML
@Order(3)  그 외      permitAll (정적 리소스)
```

**체인 순서가 중요하다.** `/api/**`가 뒤로 밀리면 REST 요청이 로그인 페이지 HTML로
리다이렉트되어 프론트에서 JSON 파싱 오류가 난다.

비밀번호는 `BCryptPasswordEncoder`로 해시하며, 관리자 전용 기능에는
`@PreAuthorize("hasRole('ADMIN')")`로 메서드 레벨 보안을 적용한다.

## 6. 협업 구조 — 인터페이스 우선 설계

리포가 둘(백엔드·프론트엔드)이므로 팀 사이를 오가는 것은 **HTTP 호출**이다.
그래서 코드를 쓰기 전에 **엔드포인트 명세를 먼저 확정**했다(`03-REST-API설계서.md`).

| 장치 | 역할 |
|---|---|
| API 계약 문서 | 요청·응답·에러를 코드보다 먼저 고정 |
| 목 서버 | 백엔드 구현 전에도 프론트가 실제 응답 형태로 개발 (병렬 착수) |
| 계약 검증 스크립트 | 구현이 계약과 일치하는지 기계가 판정 (`node seams/check-api.mjs`) |
| 화면 상태 계약 | 로딩·정상·빈 결과·에러 네 상태를 화면마다 정의 |

계약이 바뀌면 **문서·검증 스크립트·목 서버·팀 공지 네 곳이 함께** 바뀐다.

## 7. 리포 구성

```
UDT-Used_Device_Trade-backend    API 계약 문서 · 검증 스크립트 · 설계 문서가 여기 있다
UDT-Used_Device_Trade-frontend   React 앱. 계약 값을 복사하지 않고 링크로 참조한다
```

같은 값이 두 리포에 복사되면 한쪽이 반드시 낡는다. 그래서 계약 문서와 검증 스크립트는
**백엔드 리포에만** 두고, 프론트는 실행 런처로 그 스크립트를 호출한다.
