## 3. 화면별 상세 설계

### 화면 ID: SCR-001 — 상품 목록

#### 3.1.1 화면 개요

| 항목 | 내용 |
|---|---|
| 목적 | 판매중인 상품을 검색·탐색한다 |
| 진입 경로 | 로고 클릭 · 최초 진입 |
| 주요 사용자 | 전체 (비로그인 포함) |

#### 3.1.2 와이어프레임

`[D1] docs/wireframes/SCR-001.jpg — 손그림 사진 첨부`

```
┌───────────────────────────────────────────┐
│ 판매 중인 상품                              │
│ ┌─────────────────────────┐ ┌────────┐    │
│ │ 상품명으로 검색           │ │  검색   │    │
│ └─────────────────────────┘ └────────┘    │
│ ┌────┐ ┌────┐ ┌────┐ ┌────┐               │
│ │사진 │ │사진 │ │사진 │ │사진 │  ← 4열      │
│ │배지 │ │    │ │    │ │    │               │
│ │제목 │ │    │ │    │ │    │               │
│ │가격 │ │    │ │    │ │    │               │
│ └────┘ └────┘ └────┘ └────┘               │
│            ◀ 1 / 12 ▶                      │
└───────────────────────────────────────────┘
```

#### 3.1.3 화면 요소 ↔ API 매핑

| 요소 | 데이터 출처 | 비고 |
|---|---|---|
| 상품 카드 목록 | `GET /api/products` → `data.content[]` | |
| 썸네일 | `content[].thumbnailUrl` | **`null`이면 "이미지 없음"** |
| 상태 배지 | `content[].status` | 목록은 항상 판매중 |
| 페이지네이션 | `data.page` | 0-base → 표시만 +1 |
| 검색 | `?q=` | 원문 그대로 전달 |

#### 3.1.4 화면 상태 (4종)

| 상태 | 조건 | 표시 |
|---|---|---|
| 로딩 | 요청 중 | `LoadingSpinner` |
| 정상 | 결과 1건 이상 | 카드 그리드 + 페이지네이션 |
| **빈 결과** | 결과 0건 | "조건에 맞는 상품이 없습니다" + 검색어 완화 안내 |
| 에러 | 4xx/5xx·네트워크 | 서버 메시지 + **다시 시도 버튼** |

#### 3.1.5 인터랙션

- 검색 제출 → URL 쿼리 변경(`?q=…&page=0`) → 재조회
- 카드 클릭 → SCR-002
- 페이지 이동 → URL 쿼리 변경 (뒤로가기로 이전 페이지 복원)

### 화면 ID: SCR-002 — 상품 상세

| 항목 | 내용 |
|---|---|
| 목적 | 상품 정보를 확인하고 찜·구매한다 |
| 진입 | 목록 카드 클릭 |

**요소 ↔ API**

| 요소 | 출처 |
|---|---|
| 사진 갤러리 | `GET /api/products/{id}` → `images[]` (**0장이면 `[]`**) |
| 찜 버튼 | `wished` · `POST`/`DELETE /api/products/{id}/wishes` |
| 구매하기 | `POST /api/products/{id}/purchase` → 성공 시 SCR-005로 이동 |

**화면 상태**: 로딩 / 정상 / **없는 상품(404 안내 + 목록으로)** / 에러

**주요 에러 표시**

| 상황 | 화면 |
|---|---|
| 잔액 부족 | "잔액이 부족합니다" 토스트 |
| 본인 상품 | "본인이 등록한 상품은 구매할 수 없습니다" |
| 이미 거래 중 | "판매 중인 상품이 아닙니다" + 상태 갱신 |
| 비로그인 구매 시도 | 로그인 화면으로 이동 |

`[D3] 와이어프레임 첨부`

### 화면 ID: SCR-003 — 상품 등록

| 요소 | 출처 |
|---|---|
| 카테고리 선택 | `GET /api/categories` |
| 사진 업로드 | 최대 5장 · 미리보기(`URL.createObjectURL`) |
| 제출 | `POST /api/products` (multipart) |

**화면 상태**: 입력 / 제출 중(버튼 비활성) / 성공 / 검증 오류(`fields[]`를 각 입력 아래 표시)

> 제출 성공 후 **"관리자 검수 후 판매중으로 전환됩니다"** 안내를 반드시 띄운다.
> 이 문구가 없으면 등록한 상품이 목록에 없는 것을 고장으로 오해한다.

`[D3] 와이어프레임 첨부`

### 화면 ID: SCR-004 — 마이페이지

탭 4개: **내 상품 · 판매 내역 · 구매 내역 · 찜 목록**. 상단에 잔액 표시. 탭은 URL `?tab=` 이 정본.

| 탭 | `?tab=` | 출처 | 항목 클릭 시 |
|---|---|---|---|
| 내 상품 | `products` | `GET /api/me/products` (검수대기·반려 포함 모든 상태) | SCR-002 상품 상세 |
| 판매 내역 | `selling` | `GET /api/me/transactions?role=seller` | **SCR-005 거래 상세 — 판매자가 송장을 입력하는 경로** |
| 구매 내역 | `buying` | `GET /api/me/transactions?role=buyer` | SCR-005 거래 상세 |
| 찜 목록 | `wishes` | `GET /api/me/wishes` | SCR-002 상품 상세 |

> "내 상품"과 "판매 내역"을 나눈 이유 — 상품 응답에는 거래 id가 없어서 등록 상품 목록만으로는
> 판매자가 자기 거래 화면에 갈 수 없다. 시연 ④(판매자 송장 입력)가 판매 내역 탭에서 시작한다.

**화면 상태**: 탭마다 4종 — 특히 **빈 결과**("아직 등록한 상품이 없습니다")

`[D3] 와이어프레임 첨부`

### 화면 ID: SCR-005 — 거래 상세

**이 화면이 서비스의 중심이다.** 거래 상태에 따라 보이는 버튼이 달라진다.

| 거래 상태 | 구매자에게 | 판매자에게 |
|---|---|---|
| 결제완료 | 분쟁 신고 | **배송 정보 입력** |
| 배송중 | **구매 확정** · 분쟁 신고 | (대기) |
| 구매확정 | 완료 표시 | 완료 표시 |
| 분쟁 | 접수 내역·증빙 목록 | 접수 내역 |
| 환불완료 | 환불 안내 | 환불 안내 |

| 요소 | 출처 |
|---|---|
| 거래 정보 | `GET /api/transactions/{id}` |
| 배송 등록 | `PATCH /api/transactions/{id}/shipping` |
| 구매 확정 | `PATCH /api/transactions/{id}/confirm` |
| 분쟁 신고 | `POST /api/transactions/{id}/disputes` (multipart) |
| 증빙 다운로드 | `GET /api/disputes/{id}/files/{fileId}` |

**화면 상태**: 로딩 / 정상 / **권한 없음(403 — "해당 거래의 당사자가 아닙니다")** / 에러

`[D3] 와이어프레임 첨부`

---

### 화면 ID: SCR-006 / 007 — 로그인 · 회원가입

| 요소 | 출처 |
|---|---|
| 로그인 | `POST /api/auth/login` → 토큰·사용자 저장 → 이전 화면 복귀 |
| 회원가입 | `POST /api/auth/signup` → 로그인 화면으로 |

**에러 표시**: 401 "이메일 또는 비밀번호가 올바르지 않습니다" · 409 "이미 가입된 이메일입니다"

---

### 화면 ID: SCR-008 — 404 / 오류

- 없는 경로 → "페이지를 찾을 수 없습니다" + 목록 링크
- 렌더링 중 예외 → 라우트 단위 오류 화면 + 새로고침 버튼

> 이 화면이 없으면 렌더링 예외가 **흰 화면**이 되고, 개발 모드에서는 드러나지 않는다.

---

### 관리자 화면 (ADM-001 ~ 003)

| 화면 | 폼 | 처리 |
|---|---|---|
| ADM-002 상품 검수 | 승인 버튼 / 반려(사유 입력, 필수) | POST → 검증 → 실패 시 **같은 화면에 오류 표시** / 성공 시 redirect |
| ADM-003 분쟁 처리 | 증빙 다운로드 링크 · 강제 환불 / 강제 확정 | POST → redirect |

> 서버 렌더링 폼은 제출 후 **redirect**한다(PRG). 새로고침으로 같은 요청이 두 번
> 들어가는 것을 막는다. CSRF 토큰은 Thymeleaf 폼에 자동 삽입된다.
