## 슬라이드별 핵심 문장 (한 장에 한 메시지)

**#1 문제 정의**
> "중고거래 사기는 상품 정보의 문제가 아니라 **거래 과정의 문제**입니다."

**#2 해결 방식**
> "그래서 저희는 상품이 아니라 **거래 상태**를 설계의 중심에 뒀습니다."
> (검수 → 결제 → 배송 → 확정, 분쟁 분기까지 한 그림)

**#4 아키텍처**
> "서버는 계층형이고 **View가 둘입니다.** 사용자는 React, 관리자는 Thymeleaf,
> 그런데 **Service는 하나**를 공유합니다."

**#5 병렬 개발**
> "백엔드가 완성되기를 기다리지 않았습니다. **계약을 먼저 쓰고 목 서버를 띄워서**
> 첫날부터 양쪽이 동시에 달렸습니다."

**#6 상태 머신 (가장 중요한 장)**
> "구매확정 버튼 한 번에 **네 개의 데이터가 동시에** 바뀝니다.
> 하나라도 실패하면 전부 되돌아갑니다. 이게 에스크로의 실제 구현입니다."

**#10 시연**
> **영상 백업을 먼저 재생하고, 필요하면 라이브로 확인한다.**

## 시연 대본 (2분 · D10 리허설 2회 대상)

```
0:00  판매자 화면 — 상품 등록, 사진 3장                        "검수대기 상태입니다"
0:20  관리자 화면 — 검수 승인                                  "이제 목록에 뜹니다"
0:40  구매자 화면 — 검색 → 상세 → 구매                          "잔액이 빠졌습니다"
1:00  판매자 화면 — 송장 입력                                   "배송중"
1:15  구매자 화면 — 분쟁 신고 + 증빙 첨부
1:30  관리자 화면 — 증빙 다운로드 → 강제 환불                    "구매자 잔액이 복구됩니다"
1:50  (정상 경로) 다른 거래 구매확정                             "판매자에게 이제야 들어갑니다"
```

> 테스트 입력("asdf" 등) 제거 · 브라우저 창 크기 고정
