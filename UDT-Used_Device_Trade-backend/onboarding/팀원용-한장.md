## 나를 지키는 다섯 줄

```
1. 답은 SPEC.md에 있다 — 없으면 추측하지 말고 묻는다
   (잘못 짚은 결과의 책임을 혼자 지지 않는 법)

2. 내 완료 증명은 게이트 —
   백엔드  node seams/check-api.mjs
   프론트  npm run build + seams/smoke.md
   (green이면 "됐다"를 아무도 반박하지 못한다)

3. 정한 것은 문서로, 내 파트 밖은 손대지 않는다 — 구두 합의는 무효
   ("그때 그렇게 말했잖아"와 남의 버그 책임에서 나를 지키는 두 줄)

4. 30분 막히면 말한다 — 질문은 잘못이 아니라 팀 일정을 구하는 행위.
   오너는 30분 안에 답하거나 "언제 보겠다"를 답한다

5. 아침 3문장 + 하루 끝 게이트 1회 — 내 진행이 매일 기록으로 남는다
   (개별 평가 70%의 증빙이 이것이다)
```

## 아침 3문장 (스탠드업 · 15분 캡)

```
1) 어제 머지한 것 — 커밋·게이트 green/red로 말한다 ("70% 됐어요" 금지)
2) 오늘 여는 티켓 하나
3) 막힌 것 — 30분 넘게 막혔으면 여기서 반드시 말한다
```

## 하루 끝 (매일 · 5분)

```
1) 게이트 1회 → green
2) git diff 를 내가 읽는다. 한 화면(≈100줄)을 넘으면 머지하지 않고 티켓을 쪼갠다
3) 커밋·push는 내가 한다 (에이전트가 아니라) → 오너에게 머지 요청
4) worklog/<내이름>/D##.md 3줄
   1) 머지: T-014 · a1b2c3d · check-api OK
   2) 열었음: T-015
   3) 막힘: (있으면 한 줄 · 없으면 "없음")
```

> git 전체 규칙(브랜치 이름 · 커밋 메시지 · PR 템플릿 · 머지)은 [`GitHub규약.md`](../docs/참고/GitHub규약.md) 한 장. 아래는 그중 충돌 부분만.

## 충돌 났을 때 (초보용 · rebase 안 쓴다)

```
1) 절대 억지로 풀지 않는다. 채널에 "T-0XX 충돌, <파일명>" 한 줄
2) git fetch origin && git checkout origin/main -- <충돌난 파일>     ← main 것을 그대로 받는다
3) 내가 넣었던 줄만 다시 넣는다 (내 diff는 git stash show -p 나 IDE 로컬 히스토리에 있다)
4) 게이트 돌려서 green 확인 → 커밋
```

**공용 파일(`SPEC.md` · `data.sql` · `application.yml` · `package.json`)에서 충돌 나면 2번을 무조건 한다.**
남의 줄을 손으로 합치려다 지우는 사고가 첫 주에 꼭 한 번 난다. `lock` 파일은 합치지 말고 재생성한다.

## 규약 (전원)

```
1. 임의 결정 금지 — SPEC.md에 답이 없으면 메우지 말고 멈추고 오너에게 묻는다
2. 완료 주장 = 검사 출력 — "됐습니다" 산문 무효
3. 범위 밖 수정 금지 — 틀려 보여도 오너에게 보고
4. seam 관련 구두 합의 금지 — SPEC.md에 커밋되기 전까지 무효
```

## 에이전트에 위임할 때 추가 (지시서에 첨부)

```
5. 커밋·push·머지 금지 — 사람 몫
6. 게이트를 통과시키려고 게이트를 수정하지 말 것
7. 최소 diff — 전면 재작성 금지. "정리하면서 다시 짰다"는 원인을 안 고치고 새 버그를 더한다
8. 계약 밖 임의 더미로 개발 금지 — 목 서버·시드만
9. 공용 모듈(src/api·styles·config·common) 우회·재정의 금지
```

## 에이전트 지시서 양식 — `tasks/T-###.md`로 커밋한다 (말로 시키지 않는다)

```
[배경]      SPEC.md §N 본문을 그대로 붙여넣는다 (링크만 주지 않는다)
[목표]      무엇을 만들면 되는지 한 문장
[수용 기준]  node seams/check-api.mjs green
            (화면 작업이면) seams/smoke.md N번 줄 통과
[제약]      수정 허용 파일 목록 / 게이트·타 조 파일 수정 금지 / 전면 재작성 금지 / commit은 사람이
[확인 명령]  완료 확인용 실행 명령어
```

에이전트에 넣는 것은 **셋뿐**이다 — 지시서 + SPEC 해당 절 + (수정이면) diff.
리포를 통째로 넣지 않는다. `tasks/`의 누적이 곧 개인 기여 증빙이다.
