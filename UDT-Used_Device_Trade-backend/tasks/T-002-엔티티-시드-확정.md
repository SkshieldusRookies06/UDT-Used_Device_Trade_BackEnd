# T-002 — 엔티티 8종 검토·보완 · 시드 확정

**담당:** BE-A · **브랜치:** `be-entity` · **예상:** D2 · **선행:** T-001

## [배경]

`SPEC.md` §2.2 엔티티 목록과 §6 DB 스키마가 정본이다. 스캐폴드에 8종이 이미 작성돼 있으나
**팀이 직접 검토하고 보완해야 한다** — 설계서(`docs/02-Entity설계서.md`)의 근거가 이 코드다.

```
User · Category · Product · ProductImage · Wish · Transaction · Dispute · DisputeFile
+ Enum 5종 (Role · ConditionGrade · ProductStatus · TransactionStatus · DisputeStatus)
```

`SPEC.md` §6 제약조건:

| 종류 | 이름 | 업무 규칙 |
|---|---|---|
| UNIQUE | `uk_users_email` | 이메일 중복 불가 |
| UNIQUE | `uk_wishes_user_product` | 같은 상품 중복 찜 불가 |
| UNIQUE | `uk_transactions_product` | 상품당 거래 1건 |
| UNIQUE | `uk_disputes_transaction` | 거래당 분쟁 1건 |
| INDEX | `idx_products_status_created` | 목록 조회 (status, created_at) |

## [목표]

엔티티·제약조건·시드를 확정하고, 기동 시 스키마와 초기 데이터가 정상 생성되게 한다.

## [수용 기준]

- [ ] 기동 로그에 테이블 **8개** `create table` 이 뜬다 (`Review`는 P2라 만들지 않는다)
- [ ] 위 UNIQUE **5종**(`uk_categories_name` 포함) · INDEX 2종이 기동 로그에 모두 나타난다
- [ ] 시드 확인 — DB에서 직접 센다

```sql
SELECT (SELECT COUNT(*) FROM users) users,
       (SELECT COUNT(*) FROM categories) cats,
       (SELECT COUNT(*) FROM products) prods,
       (SELECT COUNT(*) FROM transactions) txns,
       (SELECT COUNT(*) FROM wishes) wishes,
       (SELECT COUNT(*) FROM disputes) disputes;
-- 기대: 4 / 5 / 22 / 4 / 2 / 1
SELECT status, COUNT(*) FROM products GROUP BY status;
-- 기대: ON_SALE 15 · INSPECTING 3 · IN_TRADE 3 · SOLD 1
SELECT status, COUNT(*) FROM transactions GROUP BY status;
-- 기대: PAID 1 · SHIPPING 1 · CONFIRMED 1 · DISPUTED 1  (거래 상세 화면이 이 4건을 본다)
```

- [ ] **모든 `@ManyToOne`·`@OneToOne`에 `fetch = FetchType.LAZY`가 명시**되어 있다
      (`grep -c "FetchType.LAZY" src/main/java/com/rookies6/udt/entity/*.java` 로 확인)
- [ ] `@Setter`가 엔티티에 없다 — 상태 변경은 의미 있는 메서드로만
- [ ] `data.sql`에 **id를 명시한 줄이 없다** (`grep -n "VALUES (1," data.sql` 무출력)
- [ ] `node seams/check-api.mjs` 의 `GET /api/products` 가 여전히 ok

## [제약]

- 수정 허용: `entity/` · `repository/` · `resources/data.sql`
- **`SPEC.md` §6의 제약조건 이름을 바꾸지 않는다** — 설계서가 그 이름을 인용한다
- 엔티티를 추가·삭제하려면 `SPEC.md` 개정이 먼저다 (§10 변경 규약)
- `Review` 엔티티는 만들지 않는다 (우선순위 P2)
