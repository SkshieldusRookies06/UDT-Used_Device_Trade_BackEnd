# T-003 — 공통 예외·응답 봉투 검증

**담당:** BE-D · **브랜치:** `be-common` · **예상:** D4 · **선행:** T-001 · T-009

> BE-D가 맡는 이유 — `BusinessException`을 가장 많이 던지는 사람이 검증하는 게 정확하다. `common/`은 BE-A 소유 파일이므로 **수정이 필요하면 BE-A에게 diff로 요청**하고, 이 티켓은 검증·보고가 본체다.

## [배경]

`SPEC.md` §0 응답 봉투 · §5 에러 코드가 정본이다.

```
성공  {"success":true,"data":…,"message":"…","timestamp":"…"}
실패  {"success":false,"statusCode":404,"code":"PRODUCT_NOT_FOUND","message":"…","timestamp":"…"}
```

**에러 생성은 `common/GlobalExceptionHandler` 한 곳에서만.** 컨트롤러마다 try-catch를
흩으면 에러 형태가 엔드포인트마다 갈라지고, 아무 데서도 안 잡은 예외는 Spring 기본 JSON
(`timestamp`·`status`·`trace`)으로 나가 계약을 어긴다.

Advice가 최소로 잡아야 할 예외 일곱:

| 예외 | → |
|---|---|
| `MethodArgumentNotValidException` | 400 + `fields[]` |
| `HttpMessageNotReadableException` | 400 |
| `MethodArgumentTypeMismatchException` | 400 (형식 불량 id) |
| `MissingServletRequestParameterException` | 400 |
| `NoResourceFoundException` | 404 `RESOURCE_NOT_FOUND` (상품 없음 `PRODUCT_NOT_FOUND`와 다른 코드) · `/admin/**`이면 다시 던져서 HTML 에러 페이지 |
| 도메인 `BusinessException` | ErrorCode의 상태 |
| `Exception` | 500 + **`log.error(…, e)` 필수** — 로그 없는 500은 시연 중 원인 추적 불가 |

## [목표]

모든 에러 응답이 공통 봉투로 나가는 것을 실제 호출로 확인한다.

## [수용 기준]

- [ ] `ErrorCode` enum에 `SPEC.md` §5의 **22개 코드가 전부** 있다
      (`grep -cE '^\s+[A-Z_]+\(' src/main/java/com/rookies6/udt/common/ErrorCode.java` → 22)
- [ ] 아래 4개 호출이 모두 공통 봉투를 반환한다

```bash
curl -s localhost:8080/api/products/999999999 | jq   # 404 PRODUCT_NOT_FOUND
curl -s localhost:8080/api/products/abc       | jq   # 400 VALIDATION_ERROR
curl -s localhost:8080/api/me                 | jq   # 401 AUTHENTICATION_REQUIRED
curl -s localhost:8080/api/nowhere            | jq   # 404
```

- [ ] 네 응답 모두 `success:false` · `code` · `statusCode` · `message` · `timestamp` 를 가진다
- [ ] `statusCode` 값이 HTTP 상태 코드와 **일치**한다
- [ ] `node seams/check-api.mjs` 의 에러 검사 항목이 ok

## [제약]

- 수정 허용: `common/` 만
- **`@JsonInclude(NON_NULL)`을 전역으로 걸지 않는다** — 빈 값 계약이 깨진다
  (`thumbnailUrl: null`이 사라지면 프론트가 키 존재로 분기할 수 없다)
- 에러 메시지 문구는 `SPEC.md` §5 표 그대로 — 화면이 이 문구를 그대로 띄운다

## [확인 명령]

```bash
node seams/check-api.mjs
grep -cE '^\s+[A-Z_]+\(' src/main/java/com/rookies6/udt/common/ErrorCode.java   # 22

# 에러 봉투를 눈으로 확인한다
curl -s localhost:8080/api/products/999999999 | jq   # 404 PRODUCT_NOT_FOUND
curl -s localhost:8080/api/products/abc       | jq   # 400 VALIDATION_ERROR
curl -s localhost:8080/api/me                 | jq   # 401 AUTHENTICATION_REQUIRED
```

> **`/api/` 아래 아무 경로나 쳐서 404를 기대하지 않는다.** permitAll 목록 밖은 전부
> `authenticated()`라서 토큰 없이 치면 **401**이 먼저 나온다(`SecurityConfig`).
> 추가 확인 둘: `curl -s localhost:8080/api/products?page=-1 | jq .code` → `VALIDATION_ERROR`(500 아님) ·
> `curl -s -o /dev/null -w '%{content_type}' localhost:8080/admin/nope` → `text/html`(JSON 아님 — Advice가 `/admin`은 되던진다)
