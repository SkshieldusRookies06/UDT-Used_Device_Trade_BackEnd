# T-022 — 거래 게이트 확장 · 테스트 보강 · 엣지 케이스

**담당:** BE-D · **브랜치:** `be-transaction-hardening` · **예상:** D5~D6 · **선행:** T-009 · T-021

## [배경]

게이트(`seams/check-api.mjs`) 9개는 상품·인증·`/api/me`만 본다. **거래 엔드포인트는 D4까지 아무도 기계로 안 본다.**
T-009가 머지된 뒤, 계약 표류를 D5 이후에도 기계가 잡도록 검사 3개를 추가하고, 상태 머신의 엣지를 테스트로 닫는다.
`seams/`는 BE-A 소유이므로 **검사 코드는 BE-A와 페어로 넣거나 diff로 넘긴다** — 게이트를 통과시키려고 게이트를 고치는 것과는 다르다.

## [목표]

거래 계약이 기계로 검증되고, 상태 머신의 경계가 전부 테스트로 증명된다.

## [수용 기준]

- [ ] 게이트에 검사 3개 추가 → **12/12**
      - `POST /api/products/{id}/purchase` → 201 · `data.buyerId`·`data.sellerId`가 문자열
      - `GET /api/transactions/{id}` → `status`가 5종 enum 중 하나 · `amountKrw` 숫자
      - `PATCH /api/transactions/{id}/confirm` (PAID 상태에) → 409 `INVALID_TRANSACTION_STATUS`
- [ ] 목 서버도 12/12 (목이 계약을 따르는지 같은 검사로)
- [ ] 테스트 추가: 잔액 정확히 0 남는 구매 · 같은 사용자가 두 상품 연속 구매 · 판매자가 자기 거래를 구매확정 시도(403) ·
      `REFUNDED` 상품을 다시 구매(ON_SALE로 복귀했으므로 성공)
- [ ] `approveInspection`·`rejectInspection`·`forceRefund`·`forceConfirm`(BR-01·02·07·08) 테스트 — BE-B의 T-018이 D6에 호출한다
- [ ] `./mvnw test` 통과 (MariaDB 기동 상태)

## [제약]

- 수정 허용: `src/test/**` · `service/TransactionService.java`(버그 수정만) · `seams/check-api.mjs`(BE-A 승인 후)
- **API 응답 형태를 바꾸지 않는다** — 바꿔야 하면 §10 변경 규약
- 게이트 검사는 **실서버와 목 서버 양쪽에서 green**이어야 머지
