# T-007 — 상품 등록 · 이미지 다중 업로드

**담당:** BE-C · **브랜치:** `be-product-write` · **예상:** D4 (반나절) · **선행:** T-005 · T-006 · **T-023(BE-A의 `FileStorageService`)**

## [배경]

계약 (`SPEC.md` §4.4):

```
POST /api/products   (multipart/form-data)
  파트: product (JSON) + images (파일 0~5개)
  제약: jpg/png/webp · 각 5MB · 최대 5장  ← 서버가 검증한다
  성공 201 · data 는 상세와 동일한 객체 · status 는 항상 INSPECTING
  에러: 400 VALIDATION_ERROR(+fields) · FILE_TYPE_NOT_ALLOWED · FILE_TOO_LARGE · 401
```

**파일 저장·검증·서빙은 BE-A의 `FileStorageService`(T-023)가 한다.** 이 티켓은 multipart를 받아
`fileStorageService.store(file, "products")`를 호출하고 `ProductImage` 행을 만드는 **연결 작업**이다.
파일 형식·용량·이름·경로 문제는 전부 T-023 소관 — 여기서 다시 검증하지 않는다.

## [목표]

사진을 포함한 상품 등록이 되고, 등록 상품은 검수 대기 상태로 목록에 나오지 않는다.

## [수용 기준]

- [ ] 사진 3장을 붙인 등록이 **201**을 반환하고 `status: "INSPECTING"`
- [ ] 등록 직후 `GET /api/products` 목록에 **나타나지 않는다**
- [ ] `GET /api/products/{id}` 에서 `images[]` 가 3개, `sortOrder` 가 0·1·2
- [ ] 6장 첨부 → 400 `FILE_COUNT_EXCEEDED` (개수 검사만 이 티켓 — 형식·용량은 T-023이 던진다)
- [ ] `.txt` 첨부 → 400 `FILE_TYPE_NOT_ALLOWED` 가 **그대로 통과되어 나온다** (T-023의 예외를 삼키지 않는다)
- [ ] 제목 공란 → 400 `VALIDATION_ERROR` + `fields[{name:"title", …}]`
- [ ] 비로그인 등록 → 401

## [제약]

- 수정 허용: `controller/ProductController.java` · `service/ProductService.java` · `dto/Product*`
- **`FileStorageService`를 만들지도 고치지도 않는다** — BE-A(T-023) 것. 부족하면 요청
- 이미지 GET 엔드포인트도 T-023 것 — 여기서 만들지 않는다

## [확인 명령]

```bash
TOKEN=$(curl -s -X POST localhost:8080/api/auth/login -H "Content-Type: application/json" \
  -d '{"email":"seller1@udt.test","password":"Test1234!"}' | jq -r .data.accessToken)

curl -s -X POST localhost:8080/api/products -H "Authorization: Bearer $TOKEN" \
  -F 'product={"title":"테스트 상품","description":"설명","priceKrw":100000,"conditionGrade":"A","categoryId":"1"};type=application/json' \
  -F 'images=@a.jpg' -F 'images=@b.jpg' | jq '.data.status, (.data.images|length)'
```
